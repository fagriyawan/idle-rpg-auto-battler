# Requirements Document

## Introduction

This document defines the requirements for a Web3-based 2D auto-battler / idle RPG game inspired by AFK Arena, Idle Heroes, and Mobile Legends Adventure. The game is a fullstack web application with blockchain wallet authentication (MetaMask). This initial phase focuses on the authentication and wallet connection system as the foundation for the game. Players authenticate using their crypto wallet address, which serves as their unique identity in the game.

## Glossary

- **Game_Client**: The 2D web frontend application that renders the game UI and handles wallet interactions
- **Backend_Service**: The server-side application handling authentication, session management, and game state persistence
- **Player**: A user identified by their blockchain wallet address
- **Wallet_Address**: A unique Ethereum-compatible address (0x-prefixed, 42 characters) that serves as the player identity
- **Wallet_Provider**: A browser extension or application (e.g., MetaMask) that manages private keys and signs transactions
- **Session_Token**: A JWT token issued by the Backend_Service after successful wallet signature verification
- **Signature_Challenge**: A unique message generated by the Backend_Service that the player signs with their wallet to prove ownership
- **Database**: The persistent storage system that stores player wallet addresses and associated game data

## Requirements

### Requirement 1: Wallet Connection via MetaMask

**User Story:** As a player, I want to connect my MetaMask wallet to the game, so that I can authenticate using my blockchain identity without needing a traditional username/password.

#### Acceptance Criteria

1. WHEN a player clicks "Connect with MetaMask", THE Game_Client SHALL request wallet connection through the MetaMask browser extension API
2. WHEN MetaMask is not installed in the player's browser, THE Game_Client SHALL display a message directing the player to install MetaMask with a link to the MetaMask download page
3. WHEN MetaMask returns the connected wallet address, THE Game_Client SHALL display the wallet address (truncated format: 0x1234...abcd) as confirmation
4. IF the player rejects the MetaMask connection request, THEN THE Game_Client SHALL display a message indicating the connection was cancelled and allow the player to retry
5. THE Game_Client SHALL detect network changes and account switches in MetaMask and update the connection state accordingly

### Requirement 2: Wallet Creation

**User Story:** As a new player without a wallet, I want guidance on creating a new wallet, so that I can start playing the game.

#### Acceptance Criteria

1. WHEN a player clicks "Create Wallet", THE Game_Client SHALL redirect the player to the MetaMask onboarding flow or display instructions for creating a new MetaMask wallet
2. THE Game_Client SHALL display a warning that the player must securely store their seed phrase and that lost seed phrases cannot be recovered
3. WHEN the player completes wallet creation and returns to the game, THE Game_Client SHALL allow the player to proceed with "Connect with MetaMask" flow

### Requirement 3: Wallet Import

**User Story:** As a player with an existing wallet on another device, I want to import my wallet, so that I can access my game account from a new device.

#### Acceptance Criteria

1. WHEN a player clicks "Import Wallet", THE Game_Client SHALL redirect the player to the MetaMask import flow or display instructions for importing an existing wallet using a seed phrase or private key
2. THE Game_Client SHALL display a security warning that seed phrases and private keys must never be shared with anyone
3. WHEN the player completes wallet import and returns to the game, THE Game_Client SHALL allow the player to proceed with "Connect with MetaMask" flow

### Requirement 4: Signature-Based Authentication

**User Story:** As a player, I want to prove ownership of my wallet without exposing my private key, so that my authentication is secure and trustless.

#### Acceptance Criteria

1. WHEN a player connects their wallet, THE Backend_Service SHALL generate a unique signature challenge message containing a nonce and timestamp
2. WHEN the Game_Client receives the challenge, THE Game_Client SHALL prompt the player to sign the message using MetaMask's personal_sign method
3. WHEN the signed message is submitted, THE Backend_Service SHALL verify the signature against the claimed wallet address using ecrecover
4. IF the signature verification succeeds, THEN THE Backend_Service SHALL issue a JWT session token with a 24-hour expiration
5. IF the signature verification fails, THEN THE Backend_Service SHALL reject the authentication and return an error indicating invalid signature
6. THE Backend_Service SHALL invalidate used nonces to prevent replay attacks

### Requirement 5: Player Account Registration

**User Story:** As a new player connecting for the first time, I want my wallet address to be registered automatically, so that I can start playing immediately without a separate registration step.

#### Acceptance Criteria

1. WHEN a wallet address authenticates successfully for the first time, THE Backend_Service SHALL create a new player record in the database with the wallet address as the primary identifier
2. THE Backend_Service SHALL store the wallet address in lowercase normalized format (checksum-independent) for consistent lookups
3. WHEN a returning player authenticates, THE Backend_Service SHALL retrieve the existing player record associated with the wallet address
4. THE Backend_Service SHALL record the first login timestamp and last login timestamp for each player account
5. IF the database operation fails during account creation, THEN THE Backend_Service SHALL return an error and not issue a session token
6. WHEN registration completes successfully, THE Game_Client SHALL display the connected wallet address and a "Start Game" button to proceed to the dashboard

### Requirement 6: Session Management and Returning Player Flow

**User Story:** As an authenticated player, I want my session to persist while I play, and when I return later I want to quickly resume without repeating the full connection flow.

#### Acceptance Criteria

1. WHILE a player has a valid session token, THE Backend_Service SHALL authorize requests without requiring re-authentication
2. WHEN a session token expires after 24 hours, THE Backend_Service SHALL reject requests and require the player to re-authenticate by signing a new challenge
3. WHEN a returning player opens the game with a valid session stored locally, THE Game_Client SHALL display the login page with the wallet address already shown, a "Start Game" button, and a "Logout" button
4. WHEN a player clicks "Start Game" with a valid session, THE Game_Client SHALL navigate directly to the dashboard without requiring a new signature
5. WHEN a player clicks "Logout", THE Game_Client SHALL clear the local session token and wallet connection, and return to the default login page with "Connect with MetaMask", "Create Wallet", and "Import Wallet" buttons
6. THE Backend_Service SHALL validate the JWT signature and expiration on every authenticated request
7. IF a request contains an invalid or tampered session token, THEN THE Backend_Service SHALL reject the request with a 401 status code and the Game_Client SHALL redirect to the default login page

### Requirement 7: Login Page UI

**User Story:** As a player, I want a clear and intuitive login page, so that I can easily connect my wallet and start playing.

#### Acceptance Criteria

1. THE Game_Client SHALL display a login page with three primary action buttons: "Connect with MetaMask", "Create Wallet", and "Import Wallet" when no active session exists
2. THE Game_Client SHALL display the game logo and title prominently on the login page
3. WHEN a wallet connection is in progress, THE Game_Client SHALL display a loading indicator and disable the connection buttons
4. WHEN authentication completes successfully, THE Game_Client SHALL display the wallet address, and a "Start Game" button
5. THE Game_Client SHALL display connection status (disconnected, connecting, connected) with appropriate visual indicators
6. IF an error occurs during any authentication step, THEN THE Game_Client SHALL display a user-friendly error message with a retry option

### Requirement 8: Game Dashboard

**User Story:** As an authenticated player, I want to see a simple dashboard after login, so that I have a landing page confirming I am in the game.

#### Acceptance Criteria

1. WHEN a player clicks "Start Game" or navigates with a valid session, THE Game_Client SHALL display the dashboard page
2. THE Game_Client SHALL display the player's wallet address (truncated format) on the dashboard as player identity
3. THE Game_Client SHALL display a "Logout" button on the dashboard that clears the session and returns to the login page
4. IF a player accesses the dashboard without a valid session, THEN THE Game_Client SHALL redirect the player to the login page
5. THE Game_Client SHALL display a welcome message with the player's last login timestamp retrieved from the Backend_Service
